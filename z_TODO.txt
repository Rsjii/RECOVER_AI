The 4-Gate Pipeline (NEW Architecture)
Gate 1: Prevent Multiple Items Per Invoice


Before ANYTHING gets queued:
  └─ Check: Does this invoice already have pending_approval item?
  └─ If YES → SKIP (one item at a time)
Gate 2: Unified Pipeline Timing (Not separate email/SMS logic)


Get last sent item (any type) + timestamp
Calculate gap days based on tier:
  ├─ Tier 1 (gentle): 7-day gap
  ├─ Tier 2 (medium): 6-day gap
  ├─ Tier 3 (urgent): 5-day gap
  └─ Tier 4 (aggressive): 4-day gap

Is NOW >= (lastSentTime + tierGapDays)?
  └─ YES → Time for next item
  └─ NO → Wait longer
Gate 3: Intelligent SMS Timing (Using Customer History)


avgEmailsNeeded = customer.payment_insights.avg_emails_before_payment

Examples:
  ├─ Fast payer (avg 1.8 emails) → Queue SMS after 2 emails
  ├─ Normal payer (avg 2.5) → Queue SMS after 3 emails
  └─ Slow payer (avg 4.2) → Queue SMS after 5 emails

Also: Apply tier adjustments based on customer history
  ├─ If slowpayer (>2.5 emails avg): Bump tier up (escalate faster)
  └─ If selfpayer (≤1.2 emails avg): Reduce tier (stay gentle)
Gate 4: Priority Queue (What to Queue Next)


Priority 1: Email (if < 5 sent + time gap met)
  ├─ Check recent rejection block (7-day block if user rejected)
  └─ Type: dunning_1, dunning_2, dunning_3, dunning_4, dunning_5

Priority 2: SMS (INTELLIGENT based on history)
  ├─ Condition: emailsSent >= Math.ceil(avgEmailsNeeded)
  ├─ Check: Email hard bounced? (escalate immediately)
  ├─ If SMS available → Queue SMS
  └─ If NO SMS → Mark as "unreachable" (human action needed)

Priority 3: Voice (Tier 4 + 90+ days) — Commented out, Phase 2

What Should Actually Happen (Final Flow)
The Complete AgentLoop Journey

Every 6 hours (cron job):
    ↓
Get unpaid invoices (status != 'paid')
    ├─ Skip demo company
    ├─ Skip paused accounts
    └─ Skip if company is deactivated
    ↓
For each invoice:
    ├─ GATE 1: Already has pending item?
    │  └─ YES → Skip (next cron)
    │
    ├─ GATE 2: Time for next item?
    │  ├─ Get last sent (any type) + timestamp
    │  ├─ Calculate tier (risk_score * 0.6 + daysOverdue/90 * 100 * 0.4)
    │  ├─ Apply dunning tone override (gentle/aggressive)
    │  ├─ Apply payment_insights adjustment (slow/self-payer)
    │  └─ Is NOW >= nextEligible? Continue...
    │
    ├─ GATE 3: Queue EMAIL or SMS or Voice?
    │  ├─ Priority 1: Email
    │  │  ├─ If emailsSent < 5 AND not recently rejected
    │  │  ├─ Check hard bounce first (if bounced → skip to SMS)
    │  │  ├─ Generate email (AI-generated via Claude API)
    │  │  ├─ Queue to pilotQueuedEmails (SHADOW mode)
    │  │  ├─ Log to agent_decisions
    │  │  └─ If ≥3 queued → CREATE notification: "Daily actions ready"
    │  │
    │  ├─ Priority 2: SMS (INTELLIGENT)
    │  │  ├─ Only if emailsSent >= Math.ceil(avgEmailsNeeded)
    │  │  ├─ Only if sms_count = 0 (first SMS)
    │  │  ├─ Only if phone opted in
    │  │  ├─ If hard bounce → queue SMS (escalate immediately)
    │  │  ├─ If NO hard bounce but not opened → queue SMS
    │  │  ├─ If SMS available → queue SMS (looks smart to user)
    │  │  ├─ If NO SMS → mark unreachable + CREATE notification
    │  │  └─ Log to agent_decisions
    │  │
    │  └─ Priority 3: Voice (TIER 4 + 90+ days)
    │     ├─ Check customer phone + opted in
    │     ├─ Check no recent voice call (24h block)
    │     ├─ Queue Twilio IVR (Phase 2)
    │     └─ Log to agent_decisions
    │
    ├─ High-Risk Alert (if risk_score ≥75 + ≥30 days overdue)
    │  └─ Send Slack notification to user
    │
    └─ Log decision for learning system (fire-and-forget)
       └─ Metadata: tier, gap, reason, avgEmailsNeeded, etc
