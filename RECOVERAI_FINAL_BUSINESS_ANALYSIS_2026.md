#### Feature 2: AP Automation (Accounts Payable)

**Problem statement:** CFOs spend 3+ hours/week on vendor invoice approvals. RecoverAI could automate.

**MVP scope:**
1. Email forwarding: `ap+{company-slug}@recoverai.com` — vendors send invoices here
2. OCR: Claude Vision extracts vendor, amount, due date from PDF
3. Storage: vendor_invoices table with OCR results
4. Dashboard widget: "You owe $45k to 12 vendors in next 30 days"
5. Approval loop: CFO gets email → "Approve $X to Vendor Y" → Yes/No buttons
6. Upsell: +$500/month add-on

**Database schema:**
```sql
CREATE TABLE vendor_invoices (
  id UUID PRIMARY KEY,
  company_id UUID NOT NULL REFERENCES companies(id),
  vendor_name VARCHAR NOT NULL,
  vendor_email VARCHAR,
  amount DECIMAL(12, 2) NOT NULL,
  due_date DATE NOT NULL,
  status VARCHAR(20) DEFAULT 'draft', -- draft | approved | rejected | paid
  ocr_raw TEXT, -- raw OCR output from Claude Vision
  ocr_confidence DECIMAL(3, 2), -- 0.0-1.0
  source_email VARCHAR, -- where it came from
  line_items JSONB, -- parsed line items if multi-item invoice
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

**Implementation:**

##### Email inbound parsing (Resend Inbound):
```typescript
// POST /api/webhooks/email/ap-receive
Headers: { 'x-resend-signature': '...' }
Body: {
  from: 'vendor@acme.com',
  to: 'ap+company-slug@recoverai.com',
  subject: 'Invoice INV-2026-001',
  text: 'Please find attached invoice for services rendered',
  attachments: [{ filename: 'invoice.pdf', content: base64(...) }]
}

1. Verify Resend webhook signature
2. Extract company_slug from "ap+{slug}@recoverai.com"
3. For each attachment (PDF/image):
   a. Call Claude Vision API → extract vendor, amount, due_date, items
   b. Create vendor_invoices row with ocr_raw + confidence
4. Queue approval_email: CFO gets "Approve $X for Vendor Y?"
5. Return 200 OK to Resend
```

##### Approval workflow:
```typescript
// POST /api/vendor-invoices/:id/approve
// POST /api/vendor-invoices/:id/reject
1. Validate company_id + user has role ≥ member
2. Update status → approved | rejected
3. If approved:
   a. Log to audit_logs
   b. Send confirmation to vendor
   c. Optionally: sync to QB (create AP entry)
```
