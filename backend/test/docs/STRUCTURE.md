# Test Folder Structure

## ✅ Organized Structure

The test folder has been reorganized for better clarity and maintainability.

### Active Directories

#### `runners/` - Test Runners
Active test runner scripts:
- `comprehensive.js` - Tests all 75+ endpoints with actual responses
- `integrations.js` - Tests all third-party integrations
- `email.js` - Email-specific functionality tests

#### `fixtures/` - Test Data
All test data and fixtures:
- `.testdata.json` - Main test data (generated by seed.js)
- `data/` - Test case data files
  - `auth-cases.json`
  - `ai-cases.json`
  - `email-cases.json`
  - `platform-cases.json`
  - `stripe-cases.json`
- `cases/` - Canonical test cases
  - `canonical-cases.json`

#### `reports/` - Test Reports
Generated test reports and documentation:
- `COMPREHENSIVE_TEST_CASES.md` - All test cases
- `TEST_RESULTS_DETAILED.md` - Detailed results
- `ACTUAL_RESPONSES.md` - API response examples
- `EMAIL_VERIFICATION.md` - Email verification report
- `INTEGRATIONS_VERIFICATION.md` - Integration test results

#### `utils/` - Utility Scripts
Utility scripts for test management:
- `seed.js` - Seed test data (creates .testdata.json)
- `cleanup.js` - Database cleanup utility

### Legacy Directory

#### `legacy/` - Deprecated Files
Old test files kept for reference:
- `run-all.js` - Old canonical runner
- `run-all-75-endpoints.js` - Old comprehensive runner
- `curl-test-all.js` - Old curl-based runner
- `scripts/` - Old test scripts

## 📝 File Paths

### Updated Paths in Runners

All runners have been updated to use the new structure:

```javascript
// Old path
const DATA_FILE = path.join(__dirname, '.testdata.json');

// New path
const DATA_FILE = path.join(__dirname, '../fixtures/.testdata.json');
```

## 🔄 Migration Notes

- All active test runners moved to `runners/`
- All test data moved to `fixtures/`
- All reports moved to `reports/`
- Old files moved to `legacy/` for reference
- Paths updated in all active scripts

## ✅ Benefits

1. **Clear Organization** - Easy to find what you need
2. **Separation of Concerns** - Runners, data, and reports separated
3. **Maintainability** - Easier to update and maintain
4. **Scalability** - Easy to add new tests or reports
5. **Clean Structure** - No clutter, everything has a place
